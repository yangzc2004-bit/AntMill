\section{Evidence Scope and Epistemic Labels}

This supplement records the frozen protocol, deterministic audit rules, full
trajectory summaries, and artifact map for the main paper. We distinguish
three evidence classes throughout:
\begin{itemize}
    \item \textbf{Frozen confirmatory experiment}: the 12-layer, three-arm
    Kimi-K2.6 \texttt{cfgpipe} run and its preregistered catastrophic-tail and
    local-admission decisions.
    \item \textbf{Retrospective replication audits}: two additional,
    independently executed cumulative self-report trajectories to which the
    exact-snapshot lock-in metric was applied after collection.
    \item \textbf{Prospective context-growth control}: a fresh six-layer run whose
    fixed-three-reference routing and two-consecutive-layer lock-in criterion
    were frozen before any new outcome was observed.
    \item \textbf{Prospective mitigation and task boundary}: a local-only
    diversity-router arm with its endpoint frozen before model calls, followed
    by a same-provider three-arm \texttt{log\_query} probe frozen before all 27
    new outcomes.
\end{itemize}
Layers within a run are coupled by shared history and are never treated as
independent samples. Cross-provider and cross-task trajectories are reported
separately rather than pooled.

\section{Testbed and Frozen Main Protocol}

\subsection{Execution Topology}

Each layer contains three MiniSWE workers that receive the same public task and
edit separate repository workspaces. A barrier closes the complete layer
before policy-selected output summaries can be delivered to the next layer.
The hidden evaluator runs only after each worker finishes. External Core or
all-test pass counts, failed-test names, and the test-collection hash are not
inserted into self-report or local-admission recipient prompts.

\subsection{Exact Worker Artifact and Admission Rules}

Each worker artifact is generated from the following schema before the
12,000-character cap:
\begin{quote}
\footnotesize\ttfamily
Worker <worker\_id>, layer <layer>.\\
Local verifier Core: <passed>/<total>; pytest exit <code>.\\
Recent MiniSWE actions and reasoning:\\
<trailing 6,000 characters from the final four assistant messages>\\
Resulting source snapshot excerpt:\\
<UTF-8 source files under the remaining artifact budget>
\end{quote}
When self-report or local admission delivers an artifact, the numeric Core line
is replaced by:
\begin{quote}
\footnotesize\ttfamily
Agent completion report: accepted without an independent smoke check;\\
external evaluation withheld.
\end{quote}
The exact self-report expression is:
\begin{quote}
\footnotesize\ttfamily
\seqsplit{\textbackslash b(pass|passes|passed|works|working|success|successful|correct|verify|verified)\textbackslash b}
\end{quote}
with case-insensitive matching over the concatenation of all assistant message
content. The local gate additionally requires at least three successful
environment commands. External evaluator outcomes are unavailable to both
rules. The recursive manager receives the public task specification, previous
playbook, and accepted source artifacts, and is instructed to retain constraints,
implementation decisions, edge cases, failure-prevention rules, and validation
procedures while resolving conflicts explicitly.

\subsection{Frozen Decision Rules}

Before new-arm outcomes, the main protocol required the cumulative
self-report arm to produce at least two post-layer-6 0/37 outcomes, including
at least one at layer 10 or later, to support recurrent complexity-tail risk.
The no-transfer arm had to produce fewer such events. The local mechanism was
supported if every observed 0/37 output with fewer than three successful
commands was rejected and never appeared in a later recipient prompt.

The catastrophic-tail criterion was falsified: cumulative self-report
produced no 0/37 outcomes in 36 worker-layer evaluations. The local mechanism
criterion passed: two zero-command 0/37 false completions were rejected and
their artifact identifiers never appeared downstream. These decisions are
separate from the later snapshot-lock-in audit.

\section{Evaluation and Identity Audit}

External score is the fraction of the frozen test collection passed. A valid
catastrophic event is exactly 0/37 after a completed model query and a
non-infrastructure evaluation. API, quota, rate-limit, or gateway failures are
not scored as benchmark failures.

For implementation identity, the auditor recursively enumerates every file in
the worker's submitted checkpoint directory, sorts paths lexicographically,
and updates SHA-256 with each UTF-8 relative path, a null byte, the complete
file bytes, and a second null byte. Three-worker exact lock-in at a layer
requires three valid snapshots with one shared directory hash. Behavioral
identity is separately measured from the set of failed test names. Exact
snapshot identity is therefore a strong repository-state equality test, but it
does not establish semantic equivalence beyond the evaluator.

The new prospective mitigation and boundary additionally freeze a
\emph{primary implementation} identity: SHA-256 of \texttt{cfgpipe.py} or
\texttt{logql.py}. The diversity router independently hashes local source files
with conventional implementation suffixes while excluding test files, caches,
and evaluator outputs. This distinction matters in the bounded control: layers
4 and 6 have two full-workspace hashes because one worker leaves an auxiliary
\texttt{ws.txt} or test file, but all workers share the same \texttt{cfgpipe.py}
from layers 2--6.

The transfer-mechanism audit also reports exact prior-primary match, normalized
source-line Jaccard, function-name Jaccard, AST-node-count signature Jaccard,
string-literal Jaccard, and the fraction of recipient source lines available
verbatim in at least one delivered snapshot excerpt. These metrics measure
alignment and prompt availability; they do not distinguish literal copying
from deterministic regeneration.

Every interpreted trajectory is checked for:
\begin{itemize}
    \item the frozen Core count, all-test count, and collection hash;
    \item at least one completed model step and no terminal model error;
    \item absence of hidden scores, failed-test names, and collection hashes in
    recipient prompts;
    \item absence of assistant actions that access benchmark catalogs, hidden
    tests, or external-evaluation paths; and
    \item stale evaluator files, which are logged but not substituted for the
    current validated evaluation.
\end{itemize}

\section{Cross-Model Tails and Mechanism Boundaries}

Across five cumulative self-report runs, DeepSeek-V4-Flash produces 2/30
valid zero-score outcomes, GLM-5 produces 0/30, and Kimi-K2.6 produces 1/24,
0/30, and 0/36 across three endpoint/run combinations. All observed zero
events are isolated or terminal. Provider and model runs are not treated as
exchangeable replications.

Recursive manager synthesis is also directionally conditional. On
\texttt{cfgpipe}, a Core-gated Kimi manager reaches exact terminal snapshot
lock-in at 32/37, while no transfer retains three snapshots at 34/37. A
DeepSeek stress probe compresses a mixed-quality bootstrap into one shared
failure signature across distinct implementations. In contrast, recursive
synthesis improves terminal normalized score by 0.047 on
\texttt{log\_query} and 0.072 on \texttt{xjq}. The separate strictly
Core-gated cumulative \texttt{log\_query} boundary ends with three distinct
snapshots and scores 0.963 versus 0.938 for no transfer. These probes establish
task- and admission-conditional direction, not a general harmful effect. The new
same-provider three-arm boundary strengthens this limit: both self-report transfer
policies retain three primary implementations at every measured layer while
raising mean all-test count relative to no transfer.

\section{Computing Environment and Claim Boundary}

The final audit and paper build use Python 3.12.12 and TeX Live 2026. Model
calls use the provider endpoints recorded in each frozen JSON configuration;
API credentials are supplied only through environment variables and are not
stored in run manifests or paper artifacts.

The evidence supports a conditional, multi-layer implementation attractor under
blinded experience transfer. Local identity-aware routing delays this attractor
by one layer on \texttt{cfgpipe} but does not prevent it; on the prospective
\texttt{log\_query}
boundary, transfer improves quality without reducing measured diversity. The
evidence does not show that context length is irrelevant, that lock-in is
permanent, that sharing is generally harmful, or that a command-count threshold
is universally optimal. Exact hashes and failed-test signatures are complementary
audited measurements bounded by the submitted repository state and frozen test
suite.
